1. ภาพรวมงานแต่ละส่วน

ดึงข้อมูลความหนาแน่นการจราจรบนถนนสายหลักของกรุงเทพฯ ทุก 15 นาทีจาก 3 แหล่ง รวมเป็นชุดข้อมูลเดียวด้วย Airflow DAG เก็บใน PostgreSQL และแสดงผลบนเว็บ Streamlit ที่อ่านจาก PostgreSQL โดยตรง ทุกแหล่งถูกแปลงเป็น schema เดียวกัน source, source_id, observed_at, road, road_key, length_m, speed_kmh, delay_s, jam_level(0–5) สำหรับ TomTom และ HERE ใช้ Travel Time Index (เวลาจริง ÷ เวลาตอนถนนโล่ง) แปลงเป็นระดับ 0–5 แบบเดียวกับ Waze

2. ปัญหาที่พบและวิธีแก้

ปัญหา 1: Clear แล้วรันซ้ำ จำนวนแถวยังเพิ่มขึ้น แม้จะใช้ UPSERT แล้ว

อาการ: กด Clear รอบเดิมใน Airflow จำนวนแถวของรอบนั้นใน traffic_record เพิ่มขึ้นทุกครั้ง

วิธีหาสาเหตุ: query COUNT(*) GROUP BY source ของรอบนั้นก่อนและหลังรันซ้ำ พบว่าแถวที่เพิ่มเป็นของ Waze ทั้งหมด เมื่อเทียบ source_id พบว่าเป็น uuid ใหม่ เพราะ Waze เป็นข้อมูลสด รันซ้ำจึงได้รายการรถติดชุดใหม่ ทำให้ UPSERT มองว่าเป็นแถวใหม่

วิธีแก้: ใน transaction เดียวกับ UPSERT ให้ลบแถวของรอบเดียวกันที่ไม่อยู่ในชุดใหม่ (เฉพาะแหล่งที่ดึงสำเร็จ) ส่วน road_status ให้ลบแล้วสร้างใหม่ทั้งรอบ ผลคือรันซ้ำกี่ครั้งจำนวนแถวก็เท่ากับ snapshot ล่าสุด ไม่เพิ่มขึ้น

ปัญหา 2: แผนที่บน dashboard ขึ้นข้อความ "Error fetching Streamlit Mapbox token"

อาการ: ส่วนอื่นของหน้าเว็บแสดงได้ปกติ แต่แผนที่ st.pydeck_chart ไม่ขึ้น

วิธีหาสาเหตุ: อ่านข้อความ error และเอกสารของ Streamlit พบว่า pydeck ใน Streamlit ต้องดึง Mapbox token จาก server ของ Streamlit ก่อนวาด ลองเปลี่ยน map_provider="carto" แล้วก็ยังขึ้น error เดิม

วิธีแก้: เปลี่ยนไปใช้ plotly.express.scatter_mapbox กับสไตล์ carto-positron ซึ่งไม่ต้องใช้ token (ลองใช้ scatter_map ก่อนแล้วได้กราฟว่าง เพราะ plotly.js ที่ติดมากับ Streamlit 1.39 ยังไม่รองรับ)

ปัญหา 3: CSS ที่ใส่เพื่อตกแต่งเว็บกลายเป็นข้อความโผล่บนหน้า

อาการ: โค้ด CSS แสดงเป็นตัวหนังสือด้านบนของหน้า และหน้าเว็บไม่มีสไตล์

วิธีหาสาเหตุ: ข้อความที่โผล่เริ่มหลังบรรทัดว่างแรกในสตริง CSS จึงสันนิษฐานว่า Markdown ของ st.markdown ปิดบล็อก HTML เมื่อเจอบรรทัดว่าง

วิธีแก้: ลบบรรทัดว่างออกก่อนส่งเข้า st.markdown(..., unsafe_allow_html=True)

งานที่ตัดออกและเหตุผล

  • Google Maps Routes API: ต้องผูกบัตรเครดิต และโควตาฟรีแบบ traffic-aware มีน้อย จึงใช้ HERE แทนซึ่งให้ข้อมูลแบบเดียวกัน
  • Dynamic Task Mapping: โบนัสได้คะแนนเท่ากับหน้าสถานะ pipeline ซึ่งยังช่วยดูว่าแหล่งไหนล่มด้วย จึงเลือกทำหน้าสถานะ
  • เส้นถนนแบบ polyline บนแผนที่: ข้อมูลเส้นของ Waze มีขนาดใหญ่ ทำให้ XCom หนัก จึงเก็บแค่จุดกลางของช่วงถนน
  • Waze alerts (อุบัติเหตุ/รายงานจากผู้ใช้): มีชื่อผู้รายงาน ขัดกับ PDPA จึงดึงเฉพาะข้อมูลรถติด (types=traffic)
